# claw2 для FreeBSD

[English](README.md) · [Русский](README.ru.md)

[claw2](https://github.com/bkisonka/claw2) — персональный ИИ-агент, который
вы размещаете сами, — как родное программное обеспечение FreeBSD: пакет
`pkg(8)`, шаблон jail и установщик, собирающий из исходников. Без Docker и
без всего, что относится к Linux-поставке: шлюз здесь — обычная служба
`rc.d` внутри jail.

Этот репозиторий — только упаковка. Кода приложения в нём нет: исходники
берутся из релиза bkisonka/claw2, и пакет — это сборка одного тега релиза,
ничего больше.

Все три способа заканчиваются одинаково: jail `claw2` с FreeBSD, пакетом и
его службой, которую нужно настроить и запустить.

## Три способа

| | Шаблон jail | Пакет | Из исходников |
|---|---|---|---|
| Что вы берёте | шаблон, около 330 МБ | пакет, около 140 МБ | этот репозиторий |
| Что скачивает ваш хост | ничего | `base.txz` своего релиза FreeBSD (165 МБ); `node22` и `sqlite-ext-vec` из репозиториев пакетов | то же, сборочные зависимости (npm, python, gmake) и из реестра npm всё, из чего собирается приложение |
| Что происходит на вашем хосте | шаблон распаковывается и запускается как jail | тонкий jail из релиза хоста, в него ставится пакет | тот же jail, и приложение собирается внутри него — минут десять |
| Релиз FreeBSD в jail | тот, из которого сделан шаблон | релиз хоста | релиз хоста |
| Чем | `scripts/install-template.sh` | `scripts/install-pkg.sh` | `scripts/install-source.sh` |

Пакет и шаблон релиза собраны на FreeBSD 15.1-RELEASE amd64 — единственном
релизе, на котором всё это проверялось. Пакет собирается под один релиз
FreeBSD, а шаблон — это userland конкретного релиза: для другого релиза
или архитектуры соберите свои скриптами ниже — они следуют за хостом, на
котором запущены. (Это не проверялось.)

## Требования

- FreeBSD и root на хосте.
- Свободный IP-адрес для jail на одном из интерфейсов хоста. Скрипты
  добавляют его как alias, пока jail работает, и убирают вместе с jail.
  Адрес должен быть из настоящей сети: jail без собственного адреса не
  имеет IP-сети вовсе, а с адресом на `lo0` он доступен только с самого
  хоста — и сам до провайдера модели не достучится.
- Ключ API любого OpenAI-совместимого провайдера моделей.

## Быстрый старт

В примерах — интерфейс `em0` и адрес `192.168.1.70`. Скрипты берутся из
клона репозитория:

```sh
git clone https://github.com/bkisonka/claw2-freebsd
cd claw2-freebsd
```

### 1. Шаблон jail

Из [релизов](https://github.com/bkisonka/claw2-freebsd/releases) (здесь —
0.2.17):

```sh
fetch https://github.com/bkisonka/claw2-freebsd/releases/download/v0.2.17/claw2-jail-0.2.17-15.1-RELEASE-amd64.txz
fetch https://github.com/bkisonka/claw2-freebsd/releases/download/v0.2.17/claw2-jail-0.2.17-15.1-RELEASE-amd64.txz.sha256
sha256 -c claw2-jail-0.2.17-15.1-RELEASE-amd64.txz.sha256

scripts/install-template.sh --template claw2-jail-0.2.17-15.1-RELEASE-amd64.txz \
    --iface em0 --ip 192.168.1.70
```

Шаблон — это готовая корневая файловая система: FreeBSD, `node22`, пакет,
учётная запись службы. Ничего не скачивается, jail поднимается за считанные
секунды. Установщик проверяет контрольную сумму (если файл `.sha256` лежит
рядом с шаблоном) и то, что шаблон сделан под релиз и архитектуру вашего
хоста.

### 2. Пакет

```sh
fetch https://github.com/bkisonka/claw2-freebsd/releases/download/v0.2.17/claw2-0.2.17.pkg
fetch https://github.com/bkisonka/claw2-freebsd/releases/download/v0.2.17/claw2-0.2.17.pkg.sha256
sha256 -c claw2-0.2.17.pkg.sha256

scripts/install-pkg.sh --pkg claw2-0.2.17.pkg --iface em0 --ip 192.168.1.70
```

Тонкий jail: база релиза вашего хоста (`base.txz`, контрольная сумма
сверяется с `MANIFEST` релиза) и пакет с зависимостями — `node22` и
`sqlite-ext-vec` — из репозиториев пакетов вашего хоста. Нужна сеть;
несколько минут.

### 3. Из исходников

```sh
scripts/install-source.sh --iface em0 --ip 192.168.1.70
```

Тот же jail, и приложение собирается внутри него собственным сборочным
скриптом порта — той же сборкой, что получает пакет. Нужны репозитории
пакетов, реестр npm и GitHub; занимает минут десять: для `better-sqlite3` и
`bcrypt` готовых бинарников под FreeBSD нет, они компилируются. Сборочные
зависимости остаются в jail. `CLAW2_SOURCE=/путь/к/исходникам` собирает
ваш тарболл или каталог вместо релиза.

## После установки

Одинаково для всех трёх. В файловой системе хоста файлы jail лежат в
`/usr/local/jails/claw2/`.

```sh
J=/usr/local/jails/claw2

# 1. Конфигурация: скопировать образец и отредактировать.
cp $J/usr/local/etc/claw2/claw2.yaml.sample $J/usr/local/etc/claw2/claw2.yaml

# 2. Ключи — только root: служба читает файл и передаёт значения шлюзу.
{ echo "OPENAI_API_KEY=sk-..."; echo "CLAW2_GATEWAY_API_KEY=$(openssl rand -hex 24)"; } \
    > $J/usr/local/etc/claw2/claw2.env
chmod 600 $J/usr/local/etc/claw2/claw2.env

# 3. Запустить.
jexec claw2 service claw2 start
fetch -qo- http://192.168.1.70:3000/health      # ok
```

Веб-интерфейс — на `http://192.168.1.70:3000`, при входе спрашивает ключ
шлюза; мобильный клиент — на `/pwa/`, руководство пользователя — на
`/wiki/`.

- **Конфигурация.** `etc/claw2/claw2.yaml` — конфигурация приложения, та
  же, что в [проекте](https://github.com/bkisonka/claw2), с умолчаниями для
  FreeBSD: скиллы в мягком сандбоксе, долговременная память выключена.
  Образец не называет сервер моделей: `llm.baseURL` закомментирован, и шлюз
  обращается к `127.0.0.1:1234` — там LM Studio слушает на десктопе, а в
  jail нет ничего. Задайте его: `https://api.openai.com/v1` для OpenAI или
  адрес собственного сервера для локальной модели.
  При старте служба забирает файл себе — веб-интерфейс сохраняет в него
  настройки. Ключи в него не попадают: `apiKey: env:OPENAI_API_KEY` берёт
  их из окружения, которое предоставляет служба.
- **Служба.** `jexec claw2 service claw2 start|stop|status`. Служба
  запускается вместе с jail, в том числе после перезагрузки
  (`claw2_enable="YES"` в `rc.conf` jail, `jail_enable="YES"` на хосте).
  Шлюз работает от имени `claw2` — учётной записи, которую создаёт пакет.
- **Журналы.** Журнал шлюза: `/usr/local/jails/claw2/var/log/claw2.log`.
  Консоль jail: `/var/log/jail_claw2_console.log` на хосте.
- **Файлы.** `/usr/local/jails/claw2/usr/local/share/claw2/` — приложение
  и его данные: `data/` с чатами; `agents/` со скиллами, их выводом в
  `agents/output` и `agents/uploads` и их библиотеками в
  `agents/node_modules`.
- **Обновление.** Новый пакет ставится поверх старого; то, что записала
  служба, пакету не принадлежит и остаётся:

  ```sh
  cp claw2-0.2.18.pkg /usr/local/jails/claw2/tmp/
  pkg -j claw2 add /tmp/claw2-0.2.18.pkg
  ```

  Новый шаблон или новая сборка из исходников: поставьте его как другой
  jail (`--name claw2-new --path /usr/local/jails/claw2-new`), перенесите
  `data/` и `etc/claw2/`, удалите старый.
- **Удаление.** `scripts/jail.sh remove claw2` останавливает jail, убирает
  его определение и удаляет каталог — вместе с чатами.

## Без jail: пакет прямо на хосте

Пакет самый обычный и может встать прямо на хост:

```sh
pkg add claw2-0.2.17.pkg
sysrc claw2_enable=YES
cp /usr/local/etc/claw2/claw2.yaml.sample /usr/local/etc/claw2/claw2.yaml
# Ключи: /usr/local/etc/claw2/claw2.env, режим 0600 — как выше.
service claw2 start
```

Приложение — в `/usr/local/share/claw2`, журнал — в `/var/log/claw2.log`.
`service claw2 stop` и `pkg delete claw2` убирают его; конфигурация, данные
и учётная запись остаются, и сообщение, которое печатает pkg, перечисляет
оставшееся.

## Сборка

Для релиза, на FreeBSD, от root, в клоне репозитория:

```sh
make pkg      # dist/claw2-<версия>.pkg и его .sha256
make jail     # dist/claw2-jail-<версия>-<релиз>-<арх>.txz, его .sha256
              # и claw2.jail.conf — подходящую stanza jail.conf(5)
make clean    # сборочные корни в work/
```

Как это устроено:

- **Приложение собирает порт.** `port/www/claw2` — порт FreeBSD вне
  официального дерева. Его `files/build-app.sh` и есть сборка: `npm ci`,
  `tsc`, веб-клиент, PWA, библиотеки скиллов и скомпилированные node-gyp
  `better-sqlite3` и `bcrypt`. Установщик, собирающий из исходников,
  вызывает тот же скрипт, поэтому две сборки не разойдутся.
- **Пакет собирается в chroot** (`scripts/build-pkg.sh`): база релиза хоста
  с `pkg`, `npm-node22`, `node22`, `python3` и `sqlite-ext-vec`, рамка
  портов и сам порт. Ничто из этого не касается системы, где идёт сборка.
- **Шаблон — это чистая база с установленным в неё пакетом**
  (`scripts/build-jail.sh`): сборочные инструменты до него не добираются.

Настройки — все необязательные, все в `scripts/common.sh`: `CLAW2_SOURCE`
(локальный тарболл или каталог вместо релиза), `CLAW2_MIRROR` (зеркало
файлов релизов FreeBSD — контрольные суммы всегда берутся с официального
сервера), `CLAW2_PKG_REPO` (описание репозитория `pkg(8)` для корней,
которые строятся здесь, — для сетей, где собственный пул серверов pkg
работает плохо), `CLAW2_RELEASE`, `CLAW2_ARCH`, `CLAW2_CACHE` (где хранить
скачанное), `CLAW2_REUSE_BUILDROOT=1` (сохранить сборочный корень
предыдущего прогона).

Новый релиз приложения: `scripts/new-release.sh <версия>` наводит порт на
него и записывает контрольную сумму его исходников. Закоммитьте, затем
`make pkg jail` и приложите `dist/` к релизу на GitHub.

## Чего на FreeBSD нет

- **Жёсткого сандбокса.** Без Docker нет одноразовых контейнеров для
  скиллов. Скиллы работают в мягком сандбоксе: модель полномочий Node.js
  (`--permission --no-addons`) и egress-гард для стандартных HTTP-стеков.
  Сырые сокеты не изолированы, как в жёстком.
- **Локальных эмбеддингов.** Под FreeBSD нет бинарника ONNX Runtime,
  поэтому долговременная память в образце конфигурации выключена. В
  приложении есть и провайдер эмбеддингов `http`; здесь он не пробовался.
- **Сайдкаров.** Приватный OCR и телефония SIP рассчитаны на
  вспомогательные бинарники (`privacy-ocr-sidecar`, `sip-media-sidecar`),
  которые шлюз ищет рядом с собой. Для FreeBSD их нет.
